## What this directory contains

- `compute_pceeb_part_a.py` — the full implementation (stdlib-only, no third-party dependency). Its module docstring documents every methodological choice made (sign convention, horizon indexing, units, missing-data rule, quantile estimator) and the exact scope boundary.
- `test_pceeb_part_a.py` — 13 focused unit tests on the pure computational core (quantile estimator, prefix-sum accumulation, missing-data skip rule). All reads/writes in these tests use small synthetic in-memory/temp-file fixtures only — no real dataset, no replay harness, no protected file.
- `outputs/` — generated by running `compute_pceeb_part_a.py`:
  - `pceeb_quantile_envelope_2020_2023.json` — primary result: the empirical quantile envelope of the prefix-cumulative realized-minus-forecast solar error, indexed by lookahead-step rank (1..19), computed from all 1,369 origins in the 2020–2023 historical dataset.
  - `pceeb_quantile_envelope_2024_odd_fixture.json` — secondary/corroboration result: the identical procedure applied independently to the 173-origin 2024 odd-day fixture (lookahead-step rank 1..24).
  - `pceeb_per_origin_prefix_errors_2020_2023_primary.csv` / `..._2024_odd_fixture_corroboration.csv` — full per-origin, per-step prefix-sum trajectories underlying the envelopes, for independent inspection/reproducibility.
  - `HASHES.txt` — SHA-256 of both inputs and all four outputs.

## Method, in one paragraph

For each forecast origin, the pre-existing `residual` column (primary dataset; independently verified this pass to equal `actual - prediction`, i.e. exactly "realized minus forecast" per the spec's own wording) — or `y_true - y_pred` computed directly (secondary dataset, which has no precomputed residual column) — is accumulated as a running (prefix) sum across that origin's chronologically-sorted sequence of lookahead steps. At each lookahead-step rank (1st, 2nd, ... hour-ahead position within the origin's own sequence — **not** the raw `horizon_hour` value; see M2 below), the resulting population of prefix sums (one value per origin) is summarized with linear-interpolation empirical quantiles at levels 0.05/0.10/0.25/0.50/0.75/0.90/0.95. No model is fit; this is a pure, deterministic, order-statistics computation.

## Methodological choices made and documented (not silently invented)

1. **Sign convention (M1):** realized − forecast = `actual − prediction`, per the PCEEB spec's exact wording. This is the opposite sign to `FORECAST_UNCERTAINTY_AUDIT.md`'s own `Error = pred − actual` convention — readers comparing figures across the two documents must flip the sign.
2. **Horizon indexing (M2):** the primary dataset has a register-documented, independently-re-confirmed indexing gap (`FORECAST_UNCERTAINTY_AUDIT.md` Section 6, `GAP-INDX-03`): most origins carry raw `horizon_hour` 1–19, a minority carry 6–24. Grouping by raw `horizon_hour` would silently mix two different conventions at the same nominal horizon. This script instead groups by **lookahead-step rank** (the origin's own 1st, 2nd, ... Nth row in horizon order), which is gap-free and well-defined for every origin, and separately reports the raw-`horizon_hour` range actually observed at each step for transparency.
3. **Units (M3):** hourly W/m² readings integrated over Δt = 1h are reported as Wh/m² with an unchanged numeric value — a dimensional identity for hourly sampling, not a fitted conversion.
4. **Missing data (M4):** zero NaN/non-numeric cells were found in either input (independently re-verified this pass). The implemented rule (exercised only by the unit tests, inert on both real inputs) is: any row with a non-numeric or NaN prediction/actual/residual field is dropped, which truncates that origin's sequence from that point forward rather than imputing a value.
5. **Quantile estimator (M5):** linear interpolation between order statistics ("Type 7", the common default), implemented in pure Python for exact reproducibility without a third-party dependency.

**No methodological choice in this list required owner risk-tolerance input or introduced a safety-relevant number** — all five are either dictated directly by the spec's own wording, verified facts about the input files, or a standard, dimensionally-exact unit identity. None of them is a reserve-shortfall ceiling, solar-credit cap, `epsilon_tol`, or any other safety-gate threshold; this script does not produce, propose, or imply any such number.

## Results summary (see the JSON files for full per-step detail)

- Primary dataset: the prefix-cumulative realized-minus-forecast error envelope widens monotonically with lookahead-step rank — e.g. the central 90% interval (q05–q95) is roughly ±10–15 Wh/m² at step 1 but roughly −1,750 to +560 Wh/m² by step 19 (19 h ahead), consistent with the autocorrelated-error finding already established in `FORECAST_UNCERTAINTY_AUDIT.md` (intra-day r = 0.63–0.78).
- Secondary (2024 odd-fixture) dataset shows the same qualitative widening pattern (step 24 q05–q95 roughly −1,000 to +855 Wh/m²), computed completely independently of the primary dataset — offered as corroboration, not validation of a fitted model (nothing was fit).
- Both envelopes are systematically **asymmetric** (wider on the negative/under-forecast side at later steps than on the positive side), which is itself a finding worth flagging to whoever designs the actual EBR-relaxation rule in a future, separately-authorized step.

This script does not import, invoke, edit, or reimplement that module, and does not run any dispatch campaign, closed-loop simulation, or replay-equivalent comparison. Part (b) remains unperformed and separately gated on a future, explicit campaign-execution authorization — consistent with `POLARIS_MASTER_DECISION_REGISTER.md` Section 16 and `N6_ANNOTATION_AND_EVIDENCE_PLANNING_REPORT.md` Section 5.

## Limitations

- This is a descriptive statistical characterization of historical forecast-error behavior. It is **not** an EBR-relaxation rule, **not** a safety threshold, and **not** validated against any closed-loop dispatch outcome (that is exactly Part (b), not performed).
- The 2020–2023 primary dataset and the 2024 secondary fixture are not a single continuous time series; the secondary result is offered only as a qualitative corroboration of the widening pattern, not a formal out-of-sample test of anything fit on the primary dataset (nothing was fit).
- As with every other document in this repository, all critical-load and EBR figures elsewhere in the project remain `SYNTHETIC_ENGINEERING_SCENARIO`; this script does not touch, assume, or depend on any critical-load constant.
- `GAP-ARCH-02` (MEPS historical archive truncated to the first 19 hours after 18:00 UTC each day) means the primary dataset's lookahead-step envelope has no step-rank equivalent to raw clock-hours 19–23 for any origin whose block happens to start early in the day; the secondary (2024) dataset does not share this truncation (complete 1–24 per origin) and is the only one of the two with full-horizon coverage.
