## 0. Framing: what the numbers are actually telling us

Before generating hypotheses, three pieces of evidence from the frozen artifacts constrain the space of plausible explanations and should be treated as data, not decoration.

**(a) The bootstrap CI narrowly straddles zero.** Stage 7.5's ΔMAE (−0.397 W/m², 95% CI [−0.792, +0.002]) is a *terrain-geometry* effect, and it is small relative to the ~37 W/m² residual. Even a physically real, correctly-engineered, zero-leakage improvement (terrain shading is about as clean a causal feature as exists in this pipeline — static DEM + astronomy) only moved the needle by ~1%. That is itself evidence: **terrain geometry is a second-order effect at this site**, not the dominant error source. Whatever is producing the other ~36 W/m² of error is something terrain cannot touch.

**(b) The diagnostics stratification is the single most informative artifact in the handoff.** `stage7_5_diagnostics.json` reports MAE of 23.7 W/m² in "shaded" hours, 53.3 W/m² in "unshaded" hours, and 22.2 W/m² in "low-sun" hours. Terrain-shaded hours are, by construction, low-magnitude (irradiance clipped toward zero by the mountain), so low absolute error there is partly a ceiling effect, not a sign the model understands shading well. The important number is the 53.3 W/m² MAE in unshaded, higher-irradiance hours — this is where the physical value at stake is largest, and where the model is worst in absolute terms. This pattern (large absolute error exactly when insolation is large and variable) is the classic signature of **cloud-driven irradiance variability being under-resolved**, not of geometric/astronomical error, which would show up more uniformly across all daylight hours regardless of shading state.

**(c) The project's own experiment history is informative by elimination.** Per `POLARIS_MASTER_HANDOFF.md`, the following have already been tried and rejected or marginal:
- MEPS ensemble spread as tabular features (Stage 6.1) — diagnostic value confirmed (ρ=0.77 with |residual|) but not exploitable by direct feature injection into a GBDT residual corrector.
- Point/ROI thermal-IR satellite features (Stage 6.2) — rejected, one fold blew the degradation gate.
- MEPS forecast-revision trajectory / "model changed its mind" signal (Stage 6.4) — promising in EVEN-CV (−0.27 W/m²) but not accepted.
- Native MEPS radiative-transfer output (RRTMG-derived SW; Stage 7.2) — rejected as redundant with existing cloud/clear-sky features.
- Clear-sky-index target reformulation (Stage 7.3) — rejected.
- MEPS pressure-level vertical cloud structure (phase-resolved LWP/IWP by layer, centroid pressure; Stage 7.4) — rejected; 3/5 folds improved but one fold degraded by +1.04 W/m², i.e., **unstable, regime-dependent signal**, not a clean win.
- Bulk-column LWP/IWP (Stage 6.6) — the only cloud-microphysics feature that *did* generalize, and it produced the largest single gain in the whole project (−1.14 W/m² EVEN-CV, −1.14 W/m² ODD).
- Terrain/horizon (Stage 7.5) — marginal, CI includes zero.

This trajectory has a clear shape: **coarse, well-conditioned, monotonic cloud-water information (Stage 6.6) helped a lot; every attempt to add finer-grained cloud detail (vertical structure, native radiation-scheme output, ensemble spread) either failed to generalize or was redundant.** That is not evidence that finer cloud detail is physically irrelevant — the ACLOUD/ecRad literature says the opposite (see §2.3) — it is evidence that **the specific representations tried so far (tabular summary statistics of an already-imperfect NWP cloud field) hit a ceiling determined by the NWP model's own cloud-forecast skill, not by feature engineering.** This is the crux of the "more variables vs. information that resolves uncertainty" distinction the brief asks for: POLARIS has been feeding the GBDT more *summaries of MEPS's own belief about clouds*. It has not yet fed it an *independent, higher-fidelity observation of the cloud/radiation state* that could correct MEPS when MEPS is wrong. Those are different things, and the diminishing/erratic returns from Stages 6.1–7.4 are consistent with having saturated the first category.

**(d) One data-quality caveat.** `stage7_5_feature_importance.csv` reports identical importance (1/35 = 0.02857) for all 35 features, including features known a priori to differ enormously in relevance (e.g., `horizon_hour` vs. `terrain_solar_obstruction_flag`). This is almost certainly a placeholder/uniform-fallback value, not a real permutation- or gain-based importance. It should not be used as evidence for or against any hypothesis below, and the current champion manifest should not be treated as having validated feature importance. This is a data-integrity note, not a critique of the frozen champion's benchmark performance.

## 1. The five causal buckets — where does the diagnostic evidence point?

| Bucket | Definition | Consistent with evidence? |
|---|---|---|
| **A. Atmospheric state prediction error** | MEPS gets the cloud/moisture/aerosol field wrong at the forecast valid time (a forecasting problem, not a translation problem) | **Strongly consistent.** MEPS is a 2.5 km deterministic NWP model; cloud-scheme parameterization error at day-ahead lead times is well documented (§2.2, §2.4) and Stage 6.1's ensemble-spread correlation (ρ=0.77 with error) is direct in-project evidence that *forecast uncertainty in the atmospheric state*, not just its translation to radiation, tracks the error. |
| **B. Cloud geometry/motion prediction error** | Correct bulk cloud amount but wrong position, timing, or edge location at t0+h | **Plausible but untested at this site.** No satellite-based cloud-motion/nowcasting stream has been evaluated (satellite coverage is marginal this far north — §2.2). This bucket is currently invisible to POLARIS; it has neither been confirmed nor ruled out. |
| **C. Radiative-transfer error (cloud state → surface flux)** | Cloud state is roughly right but the flux computed from it is wrong (plane-parallel/1D bias, terrain multiple-reflection, aerosol/AOD omission) | **Partially consistent, secondary in magnitude.** Stage 7.2 showed MEPS's own internal RRTMG-derived SW output is redundant with what POLARIS already infers — i.e., *given MEPS's cloud state*, the existing GBDT already reconstructs the RT mapping about as well as MEPS's own RT scheme does. This suggests bucket C is not where the large residual lives; the 1D/3D plane-parallel bias literature (§2.3) is real but is normally a 5–20% effect on the cloud-radiative-effect term, smaller than what's left here. |
| **D. Insufficient spatial information** | The point/column forecast misses spatially heterogeneous cloud structure relevant to a single mountain-valley station | **Consistent with the site.** Stage 5.4 (spatial NWP probes at ~2.5 km native grid) failed to generalize — but the memo's own conclusion is careful to say this "does not establish that spatial information is intrinsically uninformative," only that the *tested representation* (grid-cell-scale features) did not help. A genuinely higher-resolution, independent spatial product (e.g., cloud-resolving or satellite imagery) was never tested, because the Arctic satellite-coverage problem (§2.2) makes it hard to obtain. |
| **E. Temporal/model representation error** | The GBDT residual-correction architecture or its 24-lead-time framing systematically under-uses time information available at t0 | **Weak evidence either way.** Chronos-2 (zero-shot foundation model) beat the frozen baseline on some horizons but not others (10/24 MAE, 17/24 RMSE per the handoff) — inconclusive, not a clear win, and not pursued further as an architecture change. This bucket is not ruled out but is lower-priority than A/B/D given the concentration of error in unshaded, cloud-dominated hours. |

**Working conclusion:** the evidence most strongly implicates **A (atmospheric-state/cloud-forecast error) and D (insufficient independent spatial/observational information)**, with **B (cloud motion/position error)** as an untested but physically plausible contributor specific to this high-latitude, satellite-poor site. **C (radiative-transfer translation error)** appears to be a real but secondary contributor. **E** is not strongly implicated by the evidence in hand.

## 2. Literature synthesis by focus area

### 2.1 Cloud optical depth, LWP/IWP, effective radius, cloud phase (items 1–4)
Cloud optical thickness is described in the operational-retrieval literature as the primary determinant of cloud shading/transmittance in cloud-radiation models (the Heliosat-4/CAMS Radiation Service approach explicitly separates a clear-sky model, McClear, from a cloud-extinction model, McCloud, built on optical-depth retrievals from geostationary imagery)<cite index="9-1">the combination of multi-channel information from geostationary satellites with cloud retrieval schemes provides cloud optical properties that can be explicitly used in RTMs to account for cloud extinction and finally to calculate the surface solar radiation</cite>. This is the established mechanism: COD (and to a lesser extent effective radius, since retrieval of the two is jointly ill-posed<cite index="14-1">the problem is somehow ill-posed as the retrieval of COD depends on reff and vice versa</cite>) is what actually sets the cloud transmittance, not cloud fraction alone. POLARIS has never had a true COD retrieval or forecast; it has bulk-column LWP/IWP (a mass path, not an optical thickness, though they are correlated) forecast by MEPS's own microphysics scheme.

For cloud phase specifically, the Arctic aircraft-validation literature is direct evidence that phase/microphysics errors bias operational NWP radiation schemes at this latitude band. An ECMWF IFS/ecRad evaluation against airborne Arctic cloud observations found the model's radiative fluxes depend strongly on cloud phase partitioning and droplet concentration, and identified underestimated reflected shortwave flux over sea ice attributable in part to liquid/ice water path and droplet-number assumptions<cite index="17-1">a sensitivity study using measured surface and cloud properties is performed with ecRad to quantify the contributions of the surface albedo, cloud fraction, ice and liquid water path and cloud droplet number concentration to the observed bias</cite>. This is *causally aligned* with why Stage 6.6 (bulk LWP/IWP) worked and *why finer phase-resolved vertical structure (Stage 7.4) was directionally right but noisy* — the mechanism is real, but MEPS's own forecast of phase-resolved microphysics at pressure-level granularity is evidently not skillful enough, fold-to-fold, for a tabular GBDT to exploit reliably. This is bucket **A** error (the forecast of the state is what's wrong), not a feature-representation problem.

### 2.2 High-latitude/polar solar forecasting and satellite-coverage limits (items 7, 9, 12, 16, 19)
This is the literature that most directly explains why POLARIS's own experiment history looks the way it does. A study on Arctic-circle solar forecasting states plainly that <cite index="18-1">geostationary satellites lack coverage into the Arctic circle, limiting solar irradiance data availability</cite> and that <cite index="18-1">low solar elevation and the prevalence of snow may lead to further issues, such as satellite misinterpretation of snow as clouds, or not accurately quantifying ground albedo</cite>. A Fennoscandia-specific comparison of the exact regional NWP system POLARIS uses (MEPS) against satellite-derived irradiance and persistence confirms this is not a hypothetical concern for this project, but the operative constraint at this site<cite index="22-1">we have compared numerical weather prediction and satellite-based methods to in situ observations for solar irradiance forecasting in Fennoscandia, for intra-day and day-ahead forecasts</cite>. High-latitude solar-radiation reanalysis assessments further note that <cite index="20-1">reanalysis-based irradiance estimates can be a useful supplement when satellite irradiance is not available, although many studies have reported overestimations in reanalysis</cite> — i.e., even the fallback (reanalysis) products are known to be biased at this latitude. **Established evidence, not inference:** at 68°N, the two richest external cloud-observation streams available to mid-latitude solar forecasting (frequent geostationary imagery, and satellite cloud-motion vectors) are structurally degraded or unavailable. This is why Stage 6.2 (thermal-IR satellite) likely underperformed — not necessarily because satellite information is useless in principle, but because *at this specific latitude and viewing geometry*, satellite retrieval quality itself is compromised (snow/cloud confusion, poor sun-synchronous revisit, oblique viewing angles). This directly answers the brief's caution against assuming "satellite will help simply because satellite is higher resolution" — at Nuolja specifically, the resolution advantage may be more than offset by retrieval-quality degradation.

### 2.3 Broken-cloud / 3D radiative transfer and cloud-edge effects (items 5, 10, 11)
This is arguably the best-supported physical mechanism for the *unshaded-hour* error concentration seen in the diagnostics. The standard radiative-transfer approximation used in essentially all operational NWP radiation schemes (including MEPS's) is the plane-parallel/independent-column approximation, and the literature is explicit that this assumption breaks down in exactly the conditions that would dominate a mountain-valley station's unshaded hours (broken cumulus, cloud edges, small-scale terrain-modulated convection). A 2025 process study states the mechanism directly: <cite index="29-1">numerical weather prediction has a resolution that is too coarse to resolve individual clouds, with grid spacings on the order of 1 km... common approaches are the independent column approximation (1D instead of 3D radiative transfer), reduced spectral resolution, and reduced call frequency</cite>, and identifies four distinct 3D mechanisms (forward escape, downward escape, side escape, and cloud-gap albedo enhancement) that a 1D scheme cannot represent by construction. Independent work confirms the bias grows with resolution and cloud inhomogeneity<cite index="27-1">the higher the resolution, the larger this bias becomes... accounting for 3D radiative transfer becomes a necessity for realistic physically based correlation between cloud properties and their radiative effects</cite>, and a very recent (2026) study quantifies this specifically as a satellite-*retrieval* error source relevant to any product POLARIS might ingest: <cite index="33-1">retrievals of surface solar radiation from passive satellite instruments normally neglect the three-dimensional interaction between clouds and radiation... at the resolution of current geostationary satellites, 3D interactions can already introduce considerable errors</cite>. Field/simulation work also documents that cloud-edge enhancement effects, though often assumed to average out, <cite index="32-1">systematic biases could remain, even for daily averages</cite>. **This is the single mechanism best matched to the diagnostic pattern**: high absolute error precisely in unshaded (higher-magnitude, more solar-exposed) hours, where broken-cloud conditions produce transient, spatially localized enhancement/reduction events that a 1D column model (and any tabular feature derived from a 1D column model's own cloud summary) cannot resolve, by construction — not a data-availability problem but a **structural representation limit of the RT approximation feeding the whole pipeline**, upstream of anything POLARIS's GBDT can learn from MEPS-derived tabular features alone.

### 2.4 Cloud motion, advection, and forecast-horizon-dependent skill (items 6, 12, 13)
The nowcasting literature establishes a fairly hard skill ceiling for pure motion-based cloud forecasting, and a complementary handoff pattern with NWP: <cite index="46-1">satellite-based forecasting tools account for the short-term intra-day time horizons, typically outperforming numerical weather predictions up to 4–5 h ahead</cite>, after which optical-flow/advection skill decays because <cite index="48-1">these methods only advect the existing field and do not account for the growth or decay of clouds, their prediction horizon is limited to a few hours... typically, the first one or two hours rely on optical flow methods; as the forecast quality from optical flow begins to decline, NWP data is used to continue the forecast</cite>. This matters for POLARIS's 24-hour horizon in a specific way: **the entire forecast horizon at Nuolja is served by NWP alone**, because (a) POLARIS's horizon (24 h) is well beyond where any cloud-advection nowcast would help even at a well-observed site, and (b) even the short-horizon advection correction that mid-latitude systems use to bridge the 0–5 h gap is unavailable here due to the satellite-coverage problem in §2.2. This is a genuine, evidence-backed asymmetry between POLARIS and the mid-latitude systems the ML/solar-forecasting literature is mostly built around — not something that can be fixed by "more MEPS variables," because MEPS's cloud-field skill at h+1...h+24 is exactly the quantity in question, and no additional summary statistic of MEPS's own output can exceed MEPS's own skill at predicting cloud position/timing.

### 2.5 Mountain terrain / horizon effects (item 14)
Already directly tested (Stage 7.5). The literature confirms terrain-horizon shading is a well-posed, largely solved geometric problem once a good DEM is available (error rates as low as 0.55% MAE for the best horizon algorithms in dedicated terrain-shading studies)<cite index="37-1">the new model performs better than Hillshade and SA with an MAE of 0.55%</cite>, which is consistent with why POLARIS's own terrain experiment produced a small, physically clean, but modest gain — the geometry itself is not the bottleneck; it was already close to fully captured by `solar_elevation`/`clearsky_ghi` (Stage 7.5's own manifest notes ρ=0.88 correlation between the new terrain features and solar elevation, i.e., substantial redundancy with existing inputs). The literature does highlight a second-order terrain effect POLARIS has *not* tested: aerosol/atmospheric optical depth interacting with elevation and terrain-modulated diffuse radiation, where the HelioMont validation over the Alps found <cite index="40-1">the largest errors in diffuse and direct radiation components on shorter time scales occur during summer and for cloud-free days... as HelioMont uses monthly climatological values of atmospheric aerosol characteristics, the effects of this approximation are investigated</cite>. This points at item 8 below rather than at more terrain work.

### 2.6 Aerosol optical depth / CAMS (item 8)
This item requires directly addressing the brief's caution against assuming CAMS will help without assessing resolution and causal availability. CAMS's global atmospheric-composition forecast is causally available (forecasts, not just reanalysis, issued twice daily out to 5 days)<cite index="59-1">CAMS produces global forecasts for atmospheric composition for the next five days twice a day</cite>, at a spatial resolution of <cite index="59-1">0.4° x 0.4°</cite> — roughly 40×15 km at 68°N, i.e., **at least 15× coarser than the MEPS 2.5 km grid POLARIS already uses**, and far coarser than the single-point terrain resolution (30 m DEM) it just validated in Stage 7.5. At a remote, low-industrial-aerosol, high-latitude site like Abisko, background AOD is climatologically low and dominated by episodic events (long-range biomass-burning or Saharan dust intrusions) rather than persistent loading — exactly the kind of event a 40 km grid cell will smear out spatially and that will only matter for a small fraction of hours. This is consistent with the general finding that aerosol effects are usually secondary to cloud effects except during extreme events<cite index="10-1">clouds remain the dominant source of irradiance variability, but extreme aerosol events—such as dust storms, biomass burning, or urban smog—can also cause GHI reductions comparable to cloud cover</cite>. **Assessment: CAMS AOD is unlikely to be the primary bottleneck** given the resolution mismatch and the site's typical aerosol regime, though it could plausibly explain a small number of high-error outlier days (this is falsifiable — see §3.5).

### 2.7 Radiative-transfer parameterizations, clear-sky models, DNI/DHI decomposition (items 17–19)
The handoff record shows POLARIS never obtained a true diffuse-radiation channel: Stage 7.1's causality audit searched for a MEPS diffuse-shortwave variable and found it absent (`surface_diffuse_downwelling_shortwave_flux_in_air` — NOT VERIFIED/REJECTED; forensic audit of 243 surface variables proved this diffuse component does not exist in the MEPS archive). This means POLARIS's target (`SW_IN`, presumably global horizontal irradiance) has never been decomposed into direct-beam and diffuse components anywhere in the pipeline, despite the fact that direct and diffuse respond to clouds through entirely different physical mechanisms (direct beam is essentially binary — blocked or not, by opacity along one line of sight to the sun; diffuse is an integral over the whole sky dome and is comparatively insensitive to any single cloud element, but highly sensitive to total-sky cloud fraction and multiple scattering). A model that only ever sees the sum of these two signals cannot learn the different physics governing each, and terrain-shading effects (which POLARIS just tested) act almost entirely on the *direct* component while leaving diffuse relatively untouched — meaning a terrain feature computed against total GHI is a blurred proxy for a fundamentally beam-specific effect. This is a genuine, unaddressed gap distinct from "more cloud variables."

### 2.8 Physics-informed / hybrid ML approaches (general)
Recent hybrid architectures that separate "forecast the physical driver, then translate to flux via radiative transfer" rather than learning flux directly report meaningfully better skill than end-to-end statistical models: a 2025 study forecasting cloud optical depth and then applying an RT-based conversion to GHI reports this exact two-step design as the innovation over black-box regression<cite index="50-1">the proposed hybrid method integrates DL techniques (for COD forecasting) with a model built on radiative transfer simulations (for converting COD forecasts to GHI)</cite>. A large systematic review (120 studies, 2015–2024) of solar nowcasting reports that physics-aware architectures deliver measurable gains beyond pure statistical fitting<cite index="51-1">modern deep learning achieves 20–40% improvement over persistence baselines, with physics-aware designs substantially reducing violations of radiative constraints</cite>. This is consistent with, and gives an architectural name to, what Stage 6.6's success already demonstrated empirically at POLARIS: physically monotonic, radiatively meaningful inputs (LWP/IWP) generalize; ad hoc statistical summaries of an already-approximate NWP cloud field (ensemble spread, revision trajectories, vertical-structure centroids) generalize less reliably. **Inference (not directly evidenced by a POLARIS-specific citation):** the project's own results are a small-scale replication of this literature pattern.

## 3. Ranked hypotheses (3–5 serious breakthrough candidates)

Only hypotheses judged both physically material and realistically actionable are ranked. Each covers the ten required dimensions.

### Rank 1 — Broken-cloud / 3D radiative-transfer bias at cloud edges (bucket C, compounding with A)
- **Mechanism:** MEPS's radiation scheme (like virtually all operational NWP) uses the plane-parallel/independent-column approximation. In broken-cloud, cumulus, or terrain-channeled convective conditions — which are common in a mountain-valley environment with strong diurnal heating cycles — this assumption systematically mis-predicts the transition zones between clear and cloudy states, producing large transient over/under-predictions of direct and diffuse flux exactly when actual insolation is high (unshaded hours). <cite index="29-1">common approaches are the independent column approximation (1D instead of 3D radiative transfer), reduced spectral resolution, and reduced call frequency</cite>.
- **Observable that would measure it:** cloud-edge fraction / cloud heterogeneity index at sub-grid scale (e.g., variance of cloud optical depth within a MEPS grid cell, or a high-resolution visible-imagery-derived cloud-inhomogeneity metric), and/or the ground-truth GHI's own high-frequency variance as an implicit tag for broken-cloud regimes.
- **Causally available at t0?** Only partially. The *forecast* of sub-grid cloud heterogeneity is not something MEPS outputs; a proxy (e.g., predicted convective cloud fraction, CAPE, boundary-layer cloud-top variance) would need to be engineered from existing MEPS fields and is causally available. A true satellite-derived heterogeneity index is not available in near-real-time at 68°N with useful skill (§2.2).
- **2024 data sources:** MEPS pressure-level convective indices (CAPE, boundary-layer height, vertical velocity) already accessible per Stage 6.4/7.4 infrastructure; no new external source required for a first pass.
- **Spatial/temporal resolution:** MEPS 2.5 km / hourly — same resolution already in use; the "signal" being sought here is a *derived statistic* (heterogeneity), not a new sensor.
- **Already tested equivalent?** Not directly. Stage 6.1 (ensemble spread) is the closest proxy and *did* show strong error correlation (ρ=0.77) but failed as a direct GBDT feature — plausibly because ensemble spread conflates several distinct error sources (position error, timing error, AND heterogeneity), diluting the specific broken-cloud signal.
- **Why prior attempts may have failed:** Stage 6.1/7.4 injected either summary statistics (ensemble spread) or bulk/phase-resolved cloud *amounts*, neither of which directly encodes sub-grid spatial heterogeneity — the specific quantity 3D-RT theory says matters. Feeding a GBDT "more cloud mass" cannot substitute for "how patchy is the cloud."
- **Forecast horizons affected:** Most likely uniform across horizons (a same-day physical mechanism, not a lead-time-dependent one) but strongest during convectively active parts of the day (local midday–afternoon) regardless of lead time.
- **Leakage risk:** Low if built purely from MEPS forecast fields valid at t0+h; risk arises only if any "heterogeneity" proxy is back-calculated from the SITES SW_IN time series itself (must not condition the heterogeneity feature on the target).
- **Falsifiable experiment:** Construct a MEPS-derived convective-heterogeneity proxy (e.g., std. dev. of cloud water content across the 8–16 nearest MEPS grid cells, or CAPE/boundary-layer cloud fraction) as candidate features on top of the frozen Stage 7.5 champion; predefine the same 5-gate EVEN-CV acceptance criteria; if it fails to pass while ensemble-spread-type features have already been rejected, this specifically falsifies the "sub-grid heterogeneity is exploitable via nearby-gridpoint proxies" hypothesis without needing a true 3D-RT reforecast.

### Rank 2 — Missing causal direct/diffuse (DNI/DHI) decomposition (bucket C)
- **Mechanism:** SW_IN (GHI) is the linear sum of two physically distinct components governed by different physics (direct: line-of-sight opacity; diffuse: whole-sky-integral scattering). A model trained only on the sum cannot learn the differential sensitivity of each to cloud state, and every existing "cloud" feature (cloud_frac, LWP, terrain shading) has an implicit, un-modeled, different loading on direct vs. diffuse.
- **Observable:** MEPS accumulated DNI (`integral_of_surface_direct_normal_irradiance_wrt_time`) — already identified in Stage 7.1 as "PARTIALLY VERIFIED" and never carried forward into a champion; DHI would then be reconstructed as GHI − DNI·cos(zenith) using existing clearsky/solar-geometry fields, or estimated via a decomposition model (e.g., separation models such as those used in HelioMont/CAMS Radiation Service).
- **Causally available at t0?** Yes for the MEPS-forecast DNI component (it is a t0-issued forecast field, already flagged causally eligible in Stage 7.1); no additional external dependency required.
- **2024 data sources:** MET Norway MEPS 2.5 km deterministic archive (`thredds.met.no`), same source already in use; specifically the DNI accumulation variable flagged in Stage 7.1 but never operationalized because the matching DHI variable does not exist in the archive.
- **Spatial/temporal resolution:** 2.5 km / hourly, matching everything else in the pipeline — no resolution downgrade, unlike CAMS.
- **Already tested equivalent?** Partially — Stage 7.1 verified DNI's *causal availability* but Stage 7.2 tested only aggregate `meps_sw_hourly_derived`/`meps_net_sw_hourly_derived`/an *optional* DNI variant (E4) and found it redundant *as an additional feature on top of an already-GHI-trained model*. That is a different test from decomposing the *target* into direct+diffuse sub-models — Stage 7.2/7.3 tested target reformulation (clear-sky index) and additive DNI features, not a two-headed (direct-model + diffuse-model, recombined) architecture.
- **Why prior attempt may have failed:** Stage 7.2 added DNI as one more scalar column to a model whose target and loss function still only ever "see" total GHI error; this cannot force the model to learn the differential physics the way an explicit two-component model with two loss terms could.
- **Forecast horizons affected:** All daylight horizons, but proportionally most important at low solar elevation (large air mass, where direct/diffuse partitioning is most volatile) — i.e., likely compounds with the terrain/low-sun-hours error already flagged in the Stage 7.5 diagnostics (22.2 W/m² low-sun MAE, itself a substantial fraction of total error).
- **Leakage risk:** Low — DNI is a t0-issued MEPS forecast field, same causality class already audited and passed in Stage 7.1.
- **Falsifiable experiment:** Retrain the *architecture*, not just the feature set: two parallel GBDT residual correctors, one for a direct-beam proxy (MEPS DNI × terrain/solar-geometry attenuation) and one for a diffuse residual, recombined at evaluation time into total GHI; compare against the frozen Stage 7.5 single-target champion under the same 5-gate EVEN-CV protocol. A negative result (no improvement) would specifically falsify the "single-target blending of direct+diffuse physics is the bottleneck" hypothesis, since it isolates architecture from feature content.

### Rank 3 — MEPS cloud-forecast skill ceiling (bucket A, the "hard floor" hypothesis)
- **Mechanism:** At day-ahead lead times, a 2.5 km deterministic NWP model's cloud field itself carries irreducible forecast error (position, timing, amount) that no downstream feature engineering can correct, because the downstream model only ever has access to MEPS's belief about the atmosphere, not the atmosphere itself. This is the parsimonious explanation for why *every* MEPS-derived cloud feature tried since Stage 6.1 has produced small, fold-unstable, or redundant results: they are all functions of the same underlying (imperfect) MEPS cloud forecast.
- **Observable:** The independent variable that would test this is not a new POLARIS feature at all, but an *external, independent estimate of the true cloud state at t0+h*, against which MEPS's forecast error could be directly quantified and — if a correction signal exists — exploited. The most realistic 2024 candidate, despite the coverage caveats in §2.2, is polar-orbiting satellite cloud retrievals (e.g., VIIRS/MODIS overpasses), which do cross 68°N multiple times daily, unlike geostationary imagery.
- **Causally available at t0?** For historical/training data, yes (satellite overpasses are archived); for *forecasting* 24 h ahead, no — a satellite retrieval only tells you the cloud state at overpass time, not h+24. Its use here is diagnostic (to quantify how much of the 37 W/m² error is explained by MEPS cloud-forecast error vs. everything else) rather than as a forecast input.
- **2024 data sources:** NASA VIIRS/MODIS cloud-mask and cloud-top products (polar-orbit revisit is favorable at high latitude, several overpasses/day), NOAA CLAVR-x, or EUMETSAT polar-system products.
- **Spatial/temporal resolution:** ~375 m–1 km spatial (much finer than MEPS or CAMS); but only 2–6 overpasses/day at this latitude (much coarser temporally than the hourly MEPS/SITES cadence) — a genuine trade-off the brief specifically asked not to wave away.
- **Already tested equivalent?** No true satellite cloud-mask/cloud-top comparison against MEPS forecasts has been done; Stage 6.2's thermal-IR satellite experiment used it as an added *feature*, not as an independent skill-attribution diagnostic against MEPS.
- **Why this framing hasn't been tried:** the project has consistently framed candidates as "does adding X improve the champion," which is the right governance discipline, but has not run the complementary diagnostic study "how much of the residual error is explained by verified MEPS cloud-forecast error at the exact valid times of the worst-error hours," which would tell you *whether A is even fixable* before spending more effort on features.
- **Forecast horizons affected:** Likely increases with lead time (cloud-position/timing error compounds beyond ~6–12 h, consistent with the nowcasting-skill-decay literature in §2.4), though this project's 24 h fixed-horizon framing has not stratified error by horizon since Stage 5.2's per-horizon table (which did show improvements concentrated at "central daytime horizons," an indirect clue that early/late (low-sun) horizons are structurally harder — consistent with the Stage 7.5 low-sun MAE finding).
- **Leakage risk:** None for the diagnostic use (comparing archived satellite truth to archived MEPS forecast, offline, does not touch the SITES ODD target or feed into any model).
- **Falsifiable experiment:** For the subset of worst-error ODD hours (or a matched EVEN sample, to preserve ODD lock), pull the nearest-in-time VIIRS/MODIS cloud-top/optical-depth retrieval and compute its disagreement with the MEPS-forecast cloud field valid at the same hour. If disagreement is large and correlated with |POLARIS residual|, this is direct, falsifiable evidence that bucket A (not C or E) is the dominant remaining error source, and that further feature engineering on top of MEPS's *own* cloud belief has a hard ceiling. If disagreement is small even on high-residual hours, this hypothesis is falsified and effort should redirect to buckets C or D.

### Rank 4 (secondary, site-specific) — Low solar-elevation / high-air-mass clear-sky and RT nonlinearity
- **Mechanism:** At 68°N, a large share of daylight hours occur at high solar zenith angle even in summer, and essentially all of it in winter/shoulder seasons. Clear-sky transmittance models and RT parameterizations are typically validated and tuned against mid-latitude, lower-air-mass conditions; both aerosol/Rayleigh optical path length and cloud transmittance become more nonlinear functions of geometry at high zenith angle, and the terrain-horizon obstruction (already modeled) interacts multiplicatively with this. Stage 7.5's own diagnostics show low-sun MAE (22.2 W/m²) is not negligible relative to the daytime-average error, even though absolute irradiance magnitudes there are smaller (so *relative*/nMAE-type error there could be disproportionately large, worth checking directly, which the current diagnostics do not report).
- **Observable:** Air-mass-resolved clear-sky model error (comparing predicted vs. actual clear-sky ratio specifically during verified-clear low-sun hours), and hour-of-day-stratified nMAE (not just MAE) to check whether the 22.2 W/m² low-sun figure represents a large or small *fraction* of typical low-sun irradiance.
- **Causally available at t0?** Yes — this uses only existing solar-geometry and clear-sky fields already in the pipeline; no new data source is required, only a new stratified diagnostic.
- **2024 data sources:** none beyond what POLARIS already has (`solar_elevation`, `solar_zenith`, `clearsky_ghi`).
- **Spatial/temporal resolution:** N/A (astronomical/geometric, not observational).
- **Already tested equivalent?** Adjacent to Stage 7.5 (terrain) but not identical — Stage 7.5 tested geometric *shading*, not the separate question of whether the underlying clear-sky *transmittance* model itself is biased at high air mass independent of shading.
- **Why prior attempt may not have surfaced this:** Stage 7.5's diagnostics report absolute MAE by regime, not error normalized by the (much smaller) irradiance magnitude typical of low-sun hours — a large relative error at low sun could be hiding inside a small-looking absolute number.
- **Forecast horizons affected:** Structurally tied to time-of-day/season, not lead time — recurs at every sunrise/sunset transition regardless of horizon.
- **Leakage risk:** None — purely a re-analysis of already-computed, already-causal fields.
- **Falsifiable experiment:** Recompute the existing diagnostics stratification (shaded/unshaded/low-sun) as nMAE (error normalized by concurrent actual or clear-sky irradiance) rather than MAE alone, still entirely within the EVEN set (no ODD access needed since this reuses already-frozen predictions). If low-sun nMAE is disproportionately large relative to unshaded/shaded nMAE, this specifically implicates high-air-mass RT/clear-sky nonlinearity as a distinct, addressable mechanism; if low-sun nMAE is unremarkable once normalized, this hypothesis is falsified.

## 4. Direct answers to the seven questions

**1. What is the most likely physical bottleneck?**
Two compounding mechanisms, in this order: (i) **broken-cloud / plane-parallel radiative-transfer bias concentrated in high-insolation, cloud-active hours** (Rank 1) — best matched to the shaded/unshaded MAE asymmetry in the diagnostics; and (ii) an **irreducible MEPS day-ahead cloud-forecast skill ceiling** (Rank 3) that limits how much any tabular re-expression of MEPS's own cloud belief can help, which is the most parsimonious explanation for why Stages 6.1, 6.2, 7.2, 7.3, and 7.4 all produced small, redundant, or fold-unstable results while only the physically monotonic, coarse-grained Stage 6.6 (LWP/IWP) feature generalized.

**2. What information would directly resolve it?**
For (i): sub-grid cloud-heterogeneity/broken-cloud indicators (convective indices from MEPS, or true high-resolution imagery if it existed at this latitude) that are structurally distinct from "more cloud amount." For (ii): nothing available to POLARIS today resolves this directly — it would require either a better upstream NWP cloud forecast (outside POLARIS's control) or an independent same-time observational correction (satellite, but with the coverage/cadence caveats in §2.2/§3 Rank 3) that is not causally available at forecast-issuance time for lead times beyond the observation itself.

**3. What is the best realistically obtainable data source?**
Nothing external and new is required for the two most promising falsifiable experiments (Rank 1's convective-heterogeneity proxy and Rank 2's DNI/DHI decomposition): both can be built from data POLARIS already has causal access to (MEPS pressure-level fields; MEPS DNI, already flagged causally eligible in Stage 7.1 but never carried into a champion). This is the strongest realistic near-term source, ahead of any new satellite or CAMS product, precisely because it avoids the two failure modes (coarse resolution, satellite retrieval degradation at 68°N) that most external sources carry at this site.

**4. What is the strongest experiment POLARIS should perform first?**
The Rank 3 **diagnostic** (not a model candidate): quantify MEPS's own cloud-forecast error against an independent polar-orbiting satellite cloud product on the worst-residual hours, using only EVEN-set data. This costs no ODD access, requires no champion change, and directly answers whether the ceiling is in bucket A (MEPS state-forecast skill, likely not fixable by POLARIS) or elsewhere (buckets C/D, which are fixable by POLARIS). It should precede further feature-engineering experiments because it tells you which of Rank 1/2/4 is worth the engineering effort.

**5. Which proposed routes are unlikely to produce a meaningful improvement?**
- More MEPS tabular summary features of any kind (ensemble spread variants, additional vertical-structure statistics, revision-trajectory variants) — this category has been tried four times (Stages 6.1, 6.4, 7.2, 7.4) with small/unstable/redundant results, and the mechanism review in §2.8 explains why: they are all bounded by MEPS's own forecast skill.
- CAMS aerosol optical depth as a direct feature — resolution mismatch (≈40 km vs. 2.5 km MEPS / 30 m DEM) and this site's low, mostly-background aerosol regime make it a plausible explanation for a handful of outlier days at best, not the ~28% nMAE.
- Additional terrain/DEM refinement (e.g., finer than 30 m, or multiple-reflection/snow-albedo terrain modeling) — Stage 7.5 already showed geometric shading is a small, largely-captured effect (high correlation with existing solar-elevation features); diminishing returns are likely.
- Architecture changes that keep training on the same MEPS-derived tabular feature set without adding new physical information (e.g., swapping GBDT for another regressor) — the Chronos-2 zero-shot result (mixed, 10/24 vs 17/24 horizon wins) suggests architecture alone, without new information content, is unlikely to move the needle substantially.

**6. What would be required to move from 28.4% toward <15%?**
Based on the literature reviewed, this would very likely require an improvement in the *upstream* cloud/radiation forecast itself, not further downstream feature engineering: either (a) a demonstrably more skillful cloud-forecast product than MEPS's own scheme at this specific site (not established to exist and obtainable by this project), (b) a working 3D/sub-grid RT correction validated against ground truth at broken-cloud hours (an active but young research area — see the 2025/2026 citations in §2.3, which are largely case-study/process-level, not yet packaged as an operational correction one could bolt onto an existing NWP-derived pipeline), or (c) a fundamentally different observational anchor at t0 (e.g., a ground-based all-sky camera or short-range radar at Nuolja itself, which would sidestep the satellite-coverage problem entirely but is a new instrumentation dependency, not a data-source substitution). Absent one of these, incremental feature/architecture work on the existing MEPS-derived pipeline is more likely to yield further increments in the 0.3–1.5 percentage-point range (consistent with every accepted stage to date) than a jump to <15%.

**7. Is ≤10% scientifically realistic under current observational constraints?**
Not established as realistic with the current observational inputs (MEPS-only, no independent cloud observation at forecast time, satellite coverage structurally degraded at 68°N). Even in mid-latitude settings with dense geostationary and ground-sensor networks, state-of-the-art hybrid physics/ML nowcasting systems report skill improvements over persistence/NWP baselines in the 20–40% relative range<cite index="51-1">modern deep learning achieves 20–40% improvement over persistence baselines</cite> rather than order-of-magnitude error reductions, and those systems have observational advantages (frequent satellite imagery, larger ground networks) that Nuolja lacks. A ≤10% daytime nMAE at a single high-latitude, satellite-poor, mountain-shaded station would be an exceptional result relative to the broader published literature on solar forecasting skill at any latitude, and there is no evidence in the reviewed literature of a comparably-sited system achieving it. This should be treated as a research-inference judgment, not an established fact — it is not proven impossible, but nothing reviewed here suggests it is reachable without a new observational capability (new instrumentation, or a materially better upstream NWP cloud forecast) rather than further statistical processing of existing MEPS output.

## 5. Summary distinction the brief specifically asked for

- **"More atmospheric variables"** = additional tabular summaries derived from the same underlying MEPS forecast (ensemble spread, vertical-structure centroids, native RT output, forecast revisions). POLARIS has tried this repeatedly since Stage 6.1 with diminishing, unstable, or redundant returns — because all such variables share the same ceiling: MEPS's own skill at forecasting the true atmospheric/cloud state.
- **"Information that resolves the physical uncertainty"** = an input that is either (a) structurally distinct physics not implicit in existing features (direct/diffuse decomposition — Rank 2), (b) a genuinely independent measurement of the true state against which MEPS's forecast error can be quantified or corrected (satellite cloud-top/COD comparison — Rank 3, currently diagnostic-only, not forecast-usable at lead time), or (c) a sub-grid statistic that plane-parallel RT cannot represent by construction, rather than more of what it already represents (cloud heterogeneity — Rank 1). Only these categories have a documented mechanism, in the literature reviewed, for producing gains beyond what tabular MEPS summaries have already delivered.
