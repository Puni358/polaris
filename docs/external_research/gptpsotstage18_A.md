# Information Bottleneck Diagnosis

The Stage8.17A experiment suggests that simply adding the *magnitude* of wind or LWP differences from AROME versus MEPS did not improve solar irradiance forecasts – in fact the MAE slightly **worsened**.  This implies that AROME’s additional information may be redundant or mis‐used.  In Arctic NWP, unresolved processes (especially cloud microphysics and radiative transfer) are known to be challenging, and even a 2.5 km model like AROME-Arctic still struggles with clouds.  Comparisons of NWP versus satellite forecasts (e.g. Solis-Heliosat) show that **NWP models** generally excel at longer leads, while satellite/cloud-advection methods dominate at short leads (first 1–3 h).  Importantly, satellite-based “cloud motion vectors” (CMVs) use true observed cloud patterns: conventional methods “utilize cloud motion vectors (CMVs) from consecutive [satellite] cloud-index images to predict future cloud conditions”.  But CMVs “only [capture] cloud advection” and **cannot** handle cloud development or dissipation.  This suggests that forecasting error may stem from evolving cloud fields rather than static wind or LWP differences. 

**Stratified diagnostics (from the 4,152-row ODD data)** reportedly showed error regimes associated with surface conditions (e.g. clear vs cloudy, mountainous vs flat) and forecast bias trends over time.  The Feature Forensics likely showed weak or inconsistent correlation between the added disagreement metrics and forecast error.  In short, AROME’s *scalar* disagreements seem to carry little unique information beyond what MEPS already provides.  In effect, the “bottleneck” is not a missing AROME variable per se, but rather *the nature of the information being used*.  NWP models inherently lack true cloud advection knowledge and fine-scale terrain effects on radiation.

## Candidate New Information (smallest source)

The **smallest plausible new information source** must add something *not already implicitly present* in the Stage8 features (which include static AROME vs MEPS fields).  Three promising ideas emerge:

- **Surface/terrain orientation:**  Incorporate terrain slope/aspect and sun-angle geometry.  For example, add a feature for the station’s elevation relative to the model surface or the cosine of the solar incidence on the local slope.  Mountainous terrain creates strong local modulation of insolation (even under clear skies), and standard forecasts often treat sites as flat.  In complex terrain, clear-sky irradiance is heavily influenced by slope/aspect; under overcast conditions the effect weakens but still alters diffuse light distribution.  *Evidence FOR:* Alpine climate studies emphasize that elevation differences and slope orientation cause local irradiance biases if not accounted.  For example, Tscholl et al. show that climate models “underestimate fine-scale variability” from topography, and that incorporating slope/aspect significantly improves predictions.  In the Arctic, polar terrain and low solar angles likely make this important.  *Evidence AGAINST:* Under heavy cloud cover, terrain slopes matter less (diffuse light is more isotropic), so the feature might have little effect on fully overcast regimes.  Also, if Stage8 sites are mostly on flat sea-ice, slope may not matter much.  *Novelty:* Terrain orientation is **not** part of the original Stage8 features, which were based on model meteorology (winds, LWP, etc.).  It is external geographic information.  *Causal feasibility:* Very high – solar irradiance at the surface is physically a function of sun angle and surface orientation (especially in clear skies).  *Expected information gain:* Moderate in clear or partly clear conditions over rugged terrain; essentially zero in deep cloud.  *Falsification:* Compare forecast errors for mountain vs low-elevation sites before/after adding the feature.  If the error decreases preferentially in high-relief areas (and not in flat areas), that supports this feature’s utility.  *Experiment:* Add `elevation_diff = station_altitude – model_altitude` and/or `sun_incidence = cos(θ)` using DEM data.  Train/test the model with these new features.

- **Cloud motion / satellite imagery:**  Use real cloud observations or derived motion vectors instead of model-only winds.  For example, add a “cloud index” or short-term cloud drift speed from polar-orbiting satellites or sky imagers.  *Evidence FOR:* As noted, satellite methods capture actual cloud location and movement, improving short-term irradiance forecasts.  The HelioNet study shows >15% RMSE improvement over simple CMV methods by directly forecasting cloud images.  This implies that using *observed* cloud information could greatly reduce error.  *Evidence AGAINST:* Satellite-derived features are not “small” and may not be readily available for all points and times (especially high-latitude satellites have low resolution and geostationary view issues).  Also, Stage8 is using NWP inputs only, so adding satellite breaks that framework.  *Novelty:* This is entirely new data, not a repackaging of AROME.  *Causal feasibility:* Strong for short horizons – real clouds control irradiance.  But it is a large change (not “scalar disagreement”).  *Expected info gain:* Potentially large for intra-day forecasts (first 1–3 h) by capturing actual cloud cover changes.  *Falsification:* See if forecasts using true cloud observations (or nowcast) significantly outperform the current model.  *Experiment:* Incorporate current satellite cloud index or cloud-flag into the feature set (or use a blended satellite/NWP irradiance forecast).

- **Temporal or vertical cloud structure:**  Include time-lagged or vertical-profile information.  For example, add the forecast wind at a different level (e.g. 500 hPa) or the change in cloud variables over time.  *Evidence FOR:* If clouds are convective or stratiform, the steering winds may occur at different altitudes than 700 hPa.  Some studies use multi-layer winds or cloud-top winds to improve advection.  *Evidence AGAINST:* Simply adding another wind level duplicates information (if MEPS already has full 3D fields).  AROME vs MEPS vertical differences might not add new info beyond what the models already “know.”  *Novelty:* Low – still within NWP fields.  *Feasibility:* Moderate – requires additional data.  *Gain:* Probably small.  *Falsification:* Check if error correlates with wind shear or multi-level wind disagreement. 

Among these, **terrain/slope factors** appear the *smallest* new source (one or two simple static features) that could plausibly help.  It is *not* simply another combination of existing meteorological fields – it uses geography and solar geometry.  AROME and MEPS do not explicitly encode the local slope or orientation of the surface; adding this addresses the “representativeness” error noted.  In contrast, satellite cloud data is a powerful information source but far larger in scope (and not “scalar”) – it would shift the approach entirely toward nowcasting. 

## Evidence For/Against Terrain Feature

- *For:* Mountain climatology literature notes that even coarse models “underestimate fine-scale variability” from local topography.  In particular, solar input on slopes can differ by tens of percent from flat-ground assumptions.  The Tscholl et al. study shows that in complex terrain, combining solar geometry with cloud cover yields much better local radiation predictions.  AROME/MEPS both use grid-scale orography, so a low‐lying station in a valley would see different insolation than the model’s flat-grid prediction.  *Against:* If most forecasts are cloudy (diffuse light), the impact of slope/aspect is reduced, and a valley vs ridge might have similar diffuse irradiance under heavy overcast.  Also, if Stage8 sites are mostly flat or sea-ice (we’d need to check), the effect could be minimal.  Any improvement would be regime-dependent.  

## Causal Feasibility

Adding a *terrain/sun incidence* feature is physically sound: ground solar irradiance is directly modulated by the angle between incoming sunlight and the local surface normal.  Especially under clear or partly clear skies, misalignments cause systematic biases (e.g. a south-facing slope gets more sun).  It is feasible to compute once per station from its latitude/longitude, slope and aspect (using a DEM) and the solar zenith/azimuth.

## Expected Information Gain

We expect the gain to be **highest in clear-sky or broken-cloud regimes** over varied terrain.  It might correct a standing bias in morning vs afternoon or ridge vs valley.  In uniform cloud cover, gain will be near zero.  Overall, it is likely modest but nonzero.  Critically, it is *new* information not in the model disagreement features.  

## Falsification Criteria

- **Null hypothesis:** Forecast errors are independent of terrain orientation.  Add terrain feature and see if error improves significantly (especially at high-relief sites).  If not, reject utility.  
- **Specific test:** Stratify errors by slope: error difference in steep vs flat locations, with and without the new feature.  If steep areas show clear improvement, the feature is validated; if not, it suggests terrain isn’t the bottleneck.  

## Recommended Experiment

Compute a **terrain correction feature**. For each station:
1. Determine station altitude and the model grid altitude. Form `∆alt = station_alt – model_alt`.
2. Compute local slope aspect and solar incidence: e.g. `incidence = cos(θ)`, where θ is angle between sun vector and surface normal at station (sun vector known from time and location; surface normal from DEM).  
3. Add these as new features to the predictor (alongside the existing ones).  
Retrain/predict the irradiance and compare MAE/CI. Pay special attention to regimes (clear vs cloudy, mountain vs plain).  If MAE drops beyond statistical noise, the terrain factor is helpful; if not, it is likely not the bottleneck.

## Final Verdict

Based on the conceptual and literature analysis, the **most plausible single new information source** to test is local terrain geometry (altitude difference and slope‐incidence).  This is **not merely a repackaging** of the Stage8 features (which were all meteorological fields); it introduces external geographic information. All other sensible additions (satellite clouds, multi-level winds, temporal differencing) either greatly complicate the setup or duplicate what NWP already includes. 

**ONE PLAUSIBLE RESEARCH ROUTE:** Add a terrain/sun‐incidence feature and evaluate its impact. 

If this route shows no benefit, then likely *no small fix exists* (“No actionable route”). But if even a modest improvement appears in certain conditions, it would justify further focused experiments (e.g. more sophisticated topographic corrections).
