# Proposed Research Directions

1. **Physically-informed radiative‐transfer model (clear‐sky + cloud transmittance):** Add an explicit clear-sky irradiance baseline and compute cloud transmittance from cloud water.  For example, compute clear-sky SW_IN (using bird/Ineichen models) and estimate cloud optical depth (COD) from LWP/IWP and assumed drop size (e.g. τ≈3·LWP/(2ρ_w r_eff)).  Use a two-stream or Beer–Lambert formula to get downwelling SW from COD, solar zenith, water vapor, and surface albedo.  This hybrid “physics+ML” approach has strong precedent – Peng et al. (2026) forecasted satellite-derived COD then used radiative transfer to get GHI.  (It explicitly encodes physics and interprets factors.)  Data: NWP forecasts of LWP/IWP, column water vapor, sun position, static aerosol/climatological AOD and surface albedo.  All inputs are causal (forecast or static).  **New features:** clear-sky SW and cloud optical-transmittance.  *Why new:* The champion used LWP/IWP directly but never applied them via an RT model.  *Experiment:* Train a residual model on (SW_obs/clear_sky) or add features like “clear-sky SW_IN” and “cloud attenuation = 1–exp(–COD)”.  A successful EVEN-CV run would see a notable drop in nMAE (goal: several %-point).  *Failure modes:* Errors in assumed droplet size or missing 3D effects can bias COD; snow/surface albedo not in NWP may skew clear-sky estimate; overfitting to incorrect physics.  *Pros:* Strong physical basis (reviews note hybrid imagery+physics often outperforms pure ML).  *Cons:* Implementation complexity (need radiative code), uncertain optical assumptions.

2. **Clear-sky index normalization:** Compute a clear-sky index (measured SW_IN / model clear-sky SW) and model that instead of raw SW_IN.  Even simpler, add clear-sky SW as a feature.  This highlights cloud effects independent of solar angle.  *Why new:* No evidence this was tried.  *Data:* Same as above (solar geometry, AOD, water vapor for clear-sky model).  *Causality:* All inputs forecastable.  *Feature/model:* Feature = predicted clear-sky SW_IN; target = observed/clear-sky SW ratio (or residual).  *Experiment:* Include clear-sky SW or index in GBDT features; possibly train model on index domain.  *Success:* Reduction in error on partly cloudy conditions; improvement of baseline skill.  *Failure:* If clear-sky model is biased (especially with high albedo surfaces) it could mislead ML.  *Pros:* Low cost, well-established technique.  *Cons:* Only addresses cloud factor multiplicatively; does not add new information by itself beyond geometry (though it magnifies cloud signal).

3. **Vertical cloud structure from NWP:** Exploit layer-resolved cloud data and humidity.  MET’s MEPS provides instantaneous cloud cover at low/medium/high levels (and total), dew point and RH.  *Adds:* Altitude distribution of cloud (complements integrated LWP/IWP).  *Why not tested:* The report hints only LWP/IWP were used; separate layer fractions haven’t been emphasized.  *Data:* Use MEPS `cloud_area_fraction_{low,mid,high}`, vertical relative humidity profiles, and optionally cloud-top/base heights if available.  *Causality:* These are forecast outputs.  *Feature/model:* Add fractional cloud at each layer, dew point, and RH to the model; train residual or use in RT scheme.  *Experiment:* Include layer cloud fractions as features in GBDT.  *Success:* EVEN-CV nMAE drop by a few %-points; e.g., better error on partially cloudy cases if ML can weight high vs low clouds properly.  *Failure modes:* If MEPS misrepresents cloud layers (e.g. systematic bias), model may overfit noise.  *Pros:* Directly addresses “vertical structure” noted as lacking; physically meaningful.  *Cons:* Added features may correlate strongly (multicollinearity) and yield diminishing returns if LWP already captures most info.

4. **Cloud motion/advection using NWP winds:** Model short‐range (H1–H6) changes by advecting current cloud state.  E.g., take MEPS cloud fields (or stage input clouds) and shift them using forecast wind vectors at cloud-relevant levels.  The NOAA scheme grouped cloud objects and advected them to predict shadow patterns.  *Adds:* Implicit cloud evolution (not tested by static ML).  *Why not tested:* Previous experiments did not incorporate explicit cloud motion.  *Data:* MEPS instantaneous cloud cover + wind field at cloud levels.  *Causality:* Use only forecast data at t0.  *Feature/model:* Compute predicted cloud cover at t+1,…,t+24 via simple advection; feed resulting SW field into radiative calc.  Alternatively, add “nowcast cloud trend” features.  *Experiment:* Build a lightweight advection model (e.g. Lagrangian shift) and apply combined with clear-sky model; evaluate as separate forecast.  *Success:* Should notably improve H1–H3 forecasts (lower nMAE on short horizons).  *Failure:* Clouds rapidly form/dissipate in Arctic; simplistic advection could misplace clouds (especially vertical).  *Pros:* Based on proven nowcasting ideas; uses available NWP winds.  *Cons:* Likely only helpful for very short lead times; implementation of 3D advection is complex.  

5. **Horizon-specific models (multi-output decomposition):** Instead of treating hours 1–24 uniformly, tailor modeling by horizon.  For example, train separate models for H1–H6, H7–H12, H13–H24, or use multi-horizon ML that conditions on lead time.  *Adds:* Adaptation to differing dynamics (e.g. H1 dominated by clouds inertia, H24 more by synoptic changes).  *Why not tested:* The benchmark lumps all leads with one GBDT.  *Data:* Same predictors, but with horizon indices.  *Causality:* Not an issue (just model architecture).  *Feature/model:* E.g. include “lead time” as a feature or train distinct models. Possibly use cross-horizon LSTM.  *Experiment:* Compare a single GBDT vs separate GBDTs for short/medium/long horizons.  *Success:* Improved aggregate nMAE (e.g. better fit to near-term patterns without sacrificing far).  *Failure:* Risk of overfitting smaller splits; if errors scale similarly, improvement may be modest.  *Pros:* Conceptually simple; leverages known nonstationarity.  *Cons:* More models to tune; may yield only slight gains if underlying error process is fairly uniform.  

6. **Temporal sequence models / probabilistic forecasting:** Use sequence or state-space models to capture temporal correlation and uncertainty.  For example, an LSTM/Transformer that ingests 24-hour history (SW and/or NWP time series) to predict sequence of horizons, or a Kalman/hidden Markov model on the irradiance process.  Alternatively, switch to a probabilistic GBDT (like NGBoost) to predict distributions.  *Adds:* Explicit time-dependence and uncertainty modeling.  *Why not tested:* Current ML is pointwise GBDT with independent horizons.  *Data:* Same series (past SW, NWP time series).  *Causality:* Only past data and forecasts used.  *Feature/model:* Implement an RNN or NGBoost.  *Experiment:* Train an LSTM on [past SW, past NWP, current NWP] sequence to predict H1–H24.  *Success:* Lower nMAE especially if temporal patterns exist; possibly better calibration.  *Failure:* With 24-h contexts, limited room beyond GBDT (catastrophic for RNN to overfit, data-hungry). *Pros:* Prior work shows models like NGBoost can beat persistence and approach NWP skill.  *Cons:* GBDT already captures some lag via features; incremental gain uncertain. 

7. **Terrain/shadow modeling:** Account for terrain-induced shading by using digital elevation and sun angle.  Compute a “sky view factor” or horizon angle at each station.  *Adds:* Mountain shadow and albedo effects (especially in polar areas with low sun).  *Why not tested:* Benchmark features are purely meteorological; no explicit topo features.  *Data:* DEM and station latitude/longitude.  *Causality:* Static data only.  *Feature/model:* Precompute fraction of sky visible; as solar hour progresses, reduce clear-sky SW by this factor.  *Experiment:* Include a shading-correction factor or “max clear-sky SW” feature.  *Success:* Reduces error on stations where low sun is blocked (especially winter).  *Failure:* If terrain is flat, negligible effect.  *Pros:* Physically meaningful for mountainous sites; low risk.  *Cons:* Gains may be modest unless terrain is extreme.  

8. **Additional NWP-derived variables:** Investigate other forecast fields not yet used (CAPE, convective precipitation, aerosol optical depth, snow cover fraction, etc.).  For example, include forecast precipitable water (column H₂O), CAPE or convective inhibition (CIN), or humidity at multiple pressure levels.  *Adds:* Potential sub-grid information (e.g. imminent clouds from CAPE).  *Why not tested:* Stage6 tests focused on clouds/radiation; may have skipped CAPE or AOD.  *Data:* MEPS or AROME outputs (some variables may require new data sources, e.g. Copernicus for AOD).  *Causality:* Only forecast info.  *Feature/model:* Add these as features in GBDT.  *Experiment:* Feature-selection on new variables.  *Success:* Small gain if any (e.g. a small nMAE improvement).  *Failure:* Many may have negligible effect; noise or overfitting risk.  *Pros:* Easy to test if data available (MET often outputs humidity at standard levels).  *Cons:* Likely lower impact than core cloud variables.  

9. **(Discard) Avoid already-failed approaches:** Do *not* pursue ideas already ruled out: e.g. unsupervised “spatial cloud probes” that didn’t generalize, thermal-IR satellite at forecast time (Stage 6.2), simplistic ensemble spread features (already tried), or use of actual future observations.  These have either failed on EVEN-CV or violate causality.

# Ranking and Rationale

Based on potential impact and feasibility, the top ideas are:

- **Hybrid radiative/cloud-optical model (1):** Highest expected gain (introduces physically sound decomposition), moderate difficulty, low leak risk.  
- **Clear-sky baseline/index (2):** Moderate gain, easy to implement, well-justified physically (known in solar forecasting).  
- **Vertical cloud profile (3):** Likely helpful (exploits MEPS data) with low risk.  
- **Cloud advection (4):** High physics appeal (leverages NWP winds), likely biggest gain at very short lead times, but implementation complex.  
- **Horizon-specific modeling (5):** Conceptually straightforward, moderate gain potential.  
- **Temporal/Probabilistic models (6):** Potentially good (NGBoost style gains) but requires more complex modeling and careful calibration.  
- **Terrain shading (7):** Useful in Arctic context, easy to add, but limited to specific sites.  
- **Extra NWP features (8):** Probably minor gains; worth testing but low priority.  
- **Not to pursue (9):** Ensemble spread, thermal-IR proxy, etc. (No source needed; already known fails.)

# Top Experiments

1. **Physics-based irradiance model:** Construct a forecast using a clear-sky model plus predicted cloud transmittance.  For instance: compute clear-sky SW_IN using known algorithms, estimate COD = f(LWP,IWP,r_eff), then compute SW_IN = clear_sky·exp(–α·COD).  Train/residual-correct this combined physics model.  *Success:* EVEN-CV nMAE significantly below current (e.g. >2% gain). *Failure:* If improvement <1% or calibration poor (e.g. model misestimates cloudy days).

2. **Add vertical cloud and humidity features:** Retrain the HistGradientBoosting model including MEPS `cloud_area_fraction_low/medium/high` and 2 m dew-point/RH.  Compare EVEN-CV nMAE to baseline.  *Success:* Noticeable drop (e.g. 28.7→26% nMAE). *Failure:* No significant error change, implying these features were redundant or noisy.

3. **Sequence model (LSTM/NGBoost):** Develop a multi-step LSTM (or NGBoost) using past SW_IN and current NWP inputs to predict H1–24.  Evaluate CRPS and median nMAE.  *Success:* Beat baseline GBDT on CV (e.g. 5–10% relative improvement, following trends in literature). *Failure:* Fails to generalize (overfits) or only marginally improves, due to limited training data.

# Ideas to Avoid

- **Spatial cloud proxies:** e.g. sky cameras or nearby irradiance correlation were tested and failed.  
- **Thermal-IR satellite (Stage 6.2):** No improvement and not fully causal for short-term forecasts.  
- **Ensemble spread/sigma:** Already tested; did not reduce errors sufficiently.  
- **Non-causal data:** e.g. actual future SW_IN or reanalysis.  
- **Pure hyperparameter tuning:** Unlikely to close large gap.

# Feasibility of Targets

Current best is ~28.7% nMAE (ODD daytime). Literature suggests *major* reductions are hard. Advanced physics-based methods in mid-latitudes achieve ~8–17% RMSE (as fraction of mean irradiance). Achieving <20% nMAE (≈ 10–15% RMSE) seems plausible with significant changes (hybrid models, better cloud treatment). Hitting <15% is ambitious: it would require near best-case nowcasting performance. <=10% nMAE appears unlikely in near term without new satellite technology. In summary, **<20%** may be attainable with strong hybrid methods; **<15%** would require breakthroughs (e.g. realtime cloud profiling); **<=10%** is probably not achievable on current data and timescales.
