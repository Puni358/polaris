## 1. System Goals & Engineering Principles

POLARIS is transitioning from scientific identification research into an **operational, local-first Energy Management System (EMS)** designed for off-grid, remote microgrid infrastructure (e.g., arctic research stations, isolated microgrids).

### Primary Engineering Mandates
1. **Strictly Local & Offline-Capable:** The runtime system must operate with zero internet, zero cloud APIs, zero external databases (e.g., Supabase/Vercel), zero remote weather/NWP APIs, and zero browser connectivity. Network is used only during initial development package installation.
2. **Separation of Forecasting and Optimization:** The Energy Optimizer operates strictly against a stable `ForecastBundle` contract. The optimizer is agnostic to whether forecasts are generated by GBDT, Chronos, TimesFM, persistence, or local physics models.
3. **Contract-Driven Modular Architecture:** Clean interface isolation across Data, Forecasting, Optimization, Simulation (Digital Twin), Control, and Evaluation.
4. **Receding-Horizon Model Predictive Control (MPC):** System dispatch operates in closed-loop MPC mode ($24\text{h}$ forecast $\to 24\text{h}$ optimize $\to$ execute 1st step $\to$ update state $\to$ repeat).
5. **CLI-First Local Runtime:** Primary control and execution occur via a local Python CLI. Browser UI is deferred as a thin client wrapper.

## 6. Energy System & Modular Models

### Configuration-Driven Properties (`system/config/`)
- **`station.yaml`:** Master microgrid configuration and topology.
- **`battery.yaml`:** SOC bounds ($20\% - 95\%$), charge/discharge efficiency ($92\%$), max power ($50\text{ kW}$), capacity ($200\text{ kWh}$).
- **`diesel.yaml`:** Min/max generation ($10\text{ kW} - 100\text{ kW}$), ramp limits, fuel consumption curve parameters ($L/kWh$), startup penalty.
- **`loads.yaml`:** Critical load definitions (unmet penalty $= 10,000\$/kWh$), deferrable load time windows, curtailable load priority.
- **`optimizer.yaml`:** Solver selection (PuLP/SciPy MILP), objective weight coefficients.

## 7. Digital Twin Simulator & Receding-Horizon Control (MPC)

The `Simulator` models closed-loop physical station dynamics:
1. At step $t$, `ForecastEngine` predicts 24-hour `ForecastBundle` using only data available up to $t$.
2. `EnergyOptimizer` generates 24-hour `DispatchPlan`.
3. `Simulator` executes step 1 of `DispatchPlan` against **hidden local environmental actuals** at $t+1$.
4. Battery SOC, fuel consumption, and load compliance are updated. Actual future values are **never leaked to the optimizer**.

---

## 8. Evaluation Architecture

Decouples statistical forecasting accuracy from physical energy management performance:
- **`ForecastMetrics`:** MAE, RMSE, nMAE, Bias (evaluating $SW\_IN$, wind, and demand forecasts).
- **`EnergyManagementMetrics`:** Total fuel consumed (L), renewable utilization (%), renewable curtailment (%), battery throughput (kWh) / cycles, unmet critical load (kWh), unmet total load (kWh), reliability (%), SOC violations.
